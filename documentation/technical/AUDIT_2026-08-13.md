## 🔴 Critical — active security incident, fix before further production use

### 1. Any authenticated user can grant themselves admin / cross-tenant access

- **Where:** `supabase/migrations/20260811000007_allow_authenticated_sensitive_field_updates.sql` (lines 4–20), combined with the `user_account` UPDATE policy in `supabase/migrations/20260811000006_fix_admin_agency_null_rls.sql`.
- **What:** The `protect_user_account_sensitive_fields` trigger was rewritten to allow sensitive-field updates whenever `auth.role() = 'authenticated' OR auth.uid() IS NOT NULL` — i.e. every logged-in user, with no admin/role check at all. The accompanying RLS policy uses `WITH CHECK (true)`.
- **Impact:** Any agent can run `UPDATE user_account SET role='admin' WHERE id=<self>`, or edit another user's `agency_id` / `commission_pct`, and immediately gain administrative privileges or cross-tenant access.
- **Note:** This regression was introduced by the two most recent migrations at the time of audit — migration `...000005` had the correct role check (`get_current_user_role() IN (...)`) before it was loosened.
- **Fix:** Restore the role check in the trigger and RLS policy; remove the blanket `authenticated` / `auth.uid() IS NOT NULL` bypass.

### 2. R2 storage secret key is shipped to every browser

- **Where:** `src/lib/storage.ts:34-71`; documented as intended in `.env.example` (`VITE_R2_ACCESS_KEY_ID`, `VITE_R2_SECRET_ACCESS_KEY`).
- **What:** Vite inlines every `VITE_`-prefixed env var into the client bundle. The R2 bucket's IAM secret key is read via `import.meta.env` and ends up embedded in shipped JS.
- **Impact:** Any site visitor can extract the key from devtools/bundle and get full read/write/delete access to the entire `dream-supreme-documents` bucket, completely bypassing `verifyStorageAccessAuthorization` (which only runs client-side).
- **Fix:** Move all R2 operations (presigning, delete, authorization checks) into a server-side edge function or RPC. Never prefix secret keys with `VITE_`.

### 3. `user_account` table is world-readable across all tenants

- **Where:** `supabase/migrations/20260811000008_fix_user_account_select_rls.sql` (lines 8–9).
- **What:** SELECT policy is `USING (true)` for all authenticated users — no `agency_id` scoping.
- **Impact:** Any agent can read every other user's role, agency, commission %, and status, across all agencies, breaking multi-tenant isolation.
- **Fix:** Scope SELECT to `agency_id = get_current_agency_id() OR auth_user_id = auth.uid()`.

## 🟡 Medium

- **Dual lockfiles** — `bun.lock` and `package-lock.json` both exist and are both current, with no `packageManager` field in `package.json`. Local (Bun) and CI/Docker (npm) installs can silently resolve different transitive dependency versions.
- **Env var mismatch** — `src/components/calculators/calculator-shell.tsx:56` reads `VITE_AGENCY_SLUG`, but `.env.example` only defines `VITE_PUBLIC_AGENCY_SLUG`; the calculator silently falls back to a hardcoded default (`"dream-supreme"`) in every environment.
- **Missing env vars in `.env.example`** — `VITE_ADMIN_DOMAIN`, `VITE_WHATSAPP_API_TOKEN`, `VITE_WHATSAPP_PHONE_NUMBER_ID`, `VITE_CONVEYANCER_WEBHOOK_URL`, `VITE_XERO_CLIENT_ID`, `VITE_SAGE_API_KEY` are used in code but undocumented for new contributors.
- **God-files** — `src/routes/deals/new.tsx` (1468 lines), `src/routes/admin/users.tsx` (965), `src/routes/admin/agency.tsx` (916), `src/routes/admin/settings.tsx` (883), `src/routes/clients.tsx` (867), `src/routes/admin/commission-rules.tsx` (795) mix form state, validation, and Supabase calls in single files.
- **No E2E/integration tests** — no Playwright/Cypress config or `e2e/` directory anywhere in the repo; login and deal-capture flows are only unit-tested indirectly.
- **Dev-dependency advisories** — `undici`/`wrangler` chain has moderate/high advisories (cache poisoning, CRLF injection, cookie injection); dev-only exposure so lower real-world risk, but worth bumping `wrangler`.
- **Services swallow errors inconsistently** — `src/services/*` (11 files) have no logging discipline; some `throw` bare `Error`s, and several route-level `catch (err: any)` blocks (`pipeline.tsx:127`, `clients.tsx:258`, `admin/users.tsx:184/249`) don't confirm error reporting beyond a UI toast.

## 🟢 Low / Informational

- **ESLint warning** in `src/lib/auth.tsx:214` (`useEffect` missing `account` dependency) — verified as a lint nit, not an active bug: `refreshAccount`'s own `useCallback` dependency on `[account]` (line 164) causes it to be recreated when `account` changes, which incidentally keeps the effect from using a stale closure. A future refactor that drops `account` from `refreshAccount`'s deps would silently reintroduce a stale-closure bug — worth making the correctness explicit rather than incidental.
- **`nginx.conf`** sets `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, and `X-Frame-Options`, but has no `Content-Security-Policy` or `Strict-Transport-Security` header.
- **No SQL injection risk** found in `supabase/database/create_deal_rpc.sql` or `register_agent_rpc.sql` — both use parameterized inserts with typed function params, no dynamic string-concatenated SQL.
- **Conveyancer magic-link portal is well-built** — random 64-hex-char token, only its SHA-256 hash is stored, expiry and single-use (`used_at IS NULL`) are enforced server-side inside a `SECURITY DEFINER` function with `FOR UPDATE` row locking, preventing replay/race conditions. No issues found.
- **No formatter/component duplication** — `src/lib/format.ts` is the single source for currency and date formatting; no duplicate dialog/modal implementations found in `src/components/ui`.
- **TODO/FIXME debt is trivial** — one repo-wide hit (`src/routes/sitemap[.]xml.ts:4`, a placeholder URL comment), unrelated to security or finance.
- **No skipped or `.todo` tests** anywhere in `tests/`.
- **No `vitest.config.*`** exists (config lives implicitly via defaults) — no explicit retry/flakiness mitigation configured, though the suite currently runs clean.
- `vite.config.ts` sets `server.allowedHosts: true`, disabling Vite's dev-server host-header check — only affects `vite dev`/`preview`, not the production nginx-served build, but is a DNS-rebinding risk if the dev server is ever exposed beyond localhost.

2. **Immediately:** Move R2 credential usage server-side and stop shipping the secret key to the client (#2).
